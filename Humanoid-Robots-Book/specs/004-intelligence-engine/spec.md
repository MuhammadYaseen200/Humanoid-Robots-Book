### Edge Cases

- **What happens when a skill is invoked with an invalid argument?** (e.g., `@skill:generate-spec ""`) The skill should display usage instructions: "Usage: @skill:generate-spec '<feature description>'. Example: @skill:generate-spec 'Add dark mode toggle'." and exit without creating files.

- **How does the system handle skill execution when API rate limits are hit?** (OpenAI for embeddings, Qdrant for vector upserts) The skill should catch rate limit errors, display a user-friendly message: "Rate limit exceeded. Retry in 60 seconds.", and save progress to resume from the last successful chunk.

- **What happens when the rag-ingest skill encounters a malformed Markdown file?** (e.g., missing frontmatter, unclosed code blocks) The skill should log a warning: "Skipping docs/broken-chapter.md due to parse error on line 23.", continue processing other files, and output a summary of skipped files at the end.

- **How does the Urdu toggle handle users with JavaScript disabled?** The navbar defaults to English. The toggle button shows a message: "JavaScript required for language switching." Server-side rendering for Urdu is out of scope (documented in Assumptions).

- **What happens when a user clicks the Urdu toggle while signed in with hardware profile data?** The language preference is independent of authentication state. Changing to Urdu does not affect the user's stored GPU/RAM profile or authentication token.

- **How does the translate-urdu skill handle chapters with embedded images or diagrams?** Images remain unchanged (alt text is translated to Roman Urdu). Diagram annotations in English are NOT translated automatically; a warning is logged: "Manual review required for diagrams in chapter-X.md."

- **What happens when the landing page hero section is viewed on a screen reader?** The hero title and subtitle must have semantic HTML (`<h1>`, `<p>`). The "Get Started" button must have `aria-label="Navigate to Chapter 1"`. This requires manual accessibility testing (test-ui skill does not validate ARIA compliance automatically).

- **How does the system handle concurrent rag-ingest runs?** (Two developers run the skill simultaneously) Qdrant upsert operations use unique vector IDs based on file path + chunk index. Concurrent runs will overwrite each other's vectors for the same file, but this is acceptable since the final state is consistent (last writer wins).

## Requirements

### Functional Requirements

#### Skills Library (P+Q+P Framework)

- **FR-001**: System MUST provide a `@skill:generate-spec` command that creates a new feature specification in `specs/NNN-feature-name/spec.md` following the SDD template
- **FR-002**: generate-spec skill MUST implement The Architect persona with P+Q+P framework: Persona (specification expert), Questions (3 clarifiers for ambiguous inputs), Principles (SDD compliance, measurable success criteria)
- **FR-003**: generate-spec skill MUST auto-increment feature numbers by finding the highest existing `specs/NNN-*` directory and using NNN+1
- **FR-004**: System MUST provide a `@skill:generate-chapter` command that creates Docusaurus MDX files in `docs/module-N/chapter-M.md`
- **FR-005**: generate-chapter skill MUST implement The Author persona with P+Q+P framework: Persona (educational content writer), Questions (target audience level, prerequisites), Principles (beginner-friendly, code examples, cross-references)
- **FR-006**: generate-chapter skill MUST generate valid MDX with frontmatter (title, sidebar_position), code blocks with syntax highlighting, and Docusaurus-compatible components (admonitions, tabs)
- **FR-007**: System MUST provide a `@skill:rag-ingest` command that updates the Qdrant vector database with textbook content
- **FR-008**: rag-ingest skill MUST implement The Librarian persona with P+Q+P framework: Persona (vector database manager), Questions (none - automated), Principles (chunk size 512 tokens, overlap 50 tokens, metadata preservation)
- **FR-009**: rag-ingest skill MUST scan `docs/` recursively for `.md` files, chunk content, generate embeddings via OpenAI API, and upsert to Qdrant Cloud
- **FR-010**: rag-ingest skill MUST attach metadata to each vector: {chapter_id, file_path, module_name, chunk_index, title}
- **FR-011**: System MUST provide a `@skill:translate-urdu` command that creates Roman Urdu translations of textbook chapters
- **FR-012**: translate-urdu skill MUST implement The Linguist persona with P+Q+P framework: Persona (technical translator), Questions (dialect preference), Principles (preserve code blocks, use Roman Urdu script, maintain technical terms in English)
- **FR-013**: translate-urdu skill MUST create parallel `.ur.md` files with localized frontmatter (locale: ur) and untouched code blocks
- **FR-014**: System MUST provide a `@skill:test-ui` command that executes Playwright tests for UI components
- **FR-015**: test-ui skill MUST implement The QA persona with P+Q+P framework: Persona (automated tester), Questions (test scope), Principles (cross-browser, accessibility checks, screenshot on failure)
- **FR-016**: test-ui skill MUST generate HTML test reports in `test-results/` with pass/fail counts and failure screenshots
- **FR-017**: All skills MUST be stored as Markdown files in `.claude/skills/` with naming convention `skill-name.md`
- **FR-018**: All skill Markdown files MUST follow P+Q+P structure: ## Persona (role description), ## Questions (clarifiers), ## Principles (execution rules)

#### Landing Page Remediation

- **FR-019**: Landing page (`src/pages/index.tsx`) MUST display a hero section above the fold with title "Master Physical AI & Humanoid Robotics"
- **FR-020**: Hero section MUST include a subtitle explaining the project value proposition (free interactive textbook with RAG chatbot for ROS 2, Isaac Sim, humanoid robotics)
- **FR-021**: Hero section MUST have a "Get Started" CTA button linking to `/docs/module-1-ros2-basics/chapter-1-intro`
- **FR-022**: Landing page MUST display a feature grid with 4 cards below the hero: (1) Interactive RAG Chatbot, (2) Hardware-Aware Learning, (3) Urdu Translation, (4) Real-World Projects
- **FR-023**: Each feature card MUST include an icon, title, and 2-sentence description
- **FR-024**: Navbar MUST include an "Urdu / English" toggle button visible on all pages
- **FR-025**: Urdu toggle MUST use React Context API to manage language state globally
- **FR-026**: Clicking "Urdu" toggle MUST change navbar items to Roman Urdu: "Ghar" (Home), "Hamara Bare Main" (About), "Dakhil Hon" (Sign In), "Shamil Hon" (Sign Up)
- **FR-027**: Language preference MUST persist in browser localStorage under key "locale" with values "en" or "ur"
- **FR-028**: On page load, system MUST read localStorage.locale and set navbar language accordingly (default: "en")
- **FR-029**: Hero section MUST be responsive: single column on mobile (<768px), two-column layout (text + image) on desktop (≥768px)
- **FR-030**: Feature grid MUST be responsive: 1 card per row on mobile, 2 cards per row on tablet, 4 cards per row on desktop

#### Integration with Feature 003-better-auth

- **FR-031**: The Sign-Up modal (existing from Feature 003) MUST NOT be modified in this feature - hardware profiling form already exists

### Key Entities

- **Skill**: A reusable AI agent capability stored as Markdown in `.claude/skills/`. Contains Persona (role), Questions (clarifiers), Principles (execution rules). Invoked via `@skill:name` in Claude Code CLI.

- **Language Context**: React Context API state managing UI language preference. Contains {locale: "en" | "ur"}. Persisted in localStorage. Consumed by Navbar and future translatable components.

- **Feature Card**: UI component on landing page describing one key benefit (Interactive Chatbot, Hardware-Aware Learning, Urdu Translation, Real-World Projects). Contains icon, title, description.

## Assumptions

1. **Claude Code CLI Availability**: Assumes developers have Claude Code CLI installed and configured with API keys for OpenAI and Anthropic.

2. **Skill Execution Environment**: Skills are invoked via `@skill:name` command in Claude Code CLI, which loads Markdown from `.claude/skills/` and executes according to P+Q+P framework. The CLI handles skill registration and command parsing.

3. **Qdrant Cloud Free Tier**: Assumes Qdrant 1GB free tier is sufficient for initial textbook content (~100 chapters, ~500,000 words). Monitoring is required to avoid exceeding limits.

4. **OpenAI Embedding Model**: Assumes `text-embedding-3-small` model is used for rag-ingest skill (cost-effective, 1536 dimensions). Model selection is configurable via environment variable.

5. **Roman Urdu Dialect**: Assumes Roman Urdu translation uses standard Urdu romanization conventions (not regional dialects like Punjabi-influenced Urdu). Technical terms remain in English.

6. **Browser LocalStorage Availability**: Assumes users have localStorage enabled for language preference persistence. If disabled, the system defaults to English on every page load.

7. **Authentication Integration**: Assumes Feature 003-better-auth is already deployed and functional. This feature does NOT modify the hardware profiling form or authentication logic.

8. **Docusaurus Version**: Assumes Docusaurus v3.x with React 18. Skills that generate MDX must use compatible syntax (e.g., MDXv2 format).

9. **No Server-Side Rendering for Urdu**: The Urdu toggle is client-side only (React Context + localStorage). Server-side rendering of Urdu pages is out of scope.

10. **Playwright Browser Installation**: Assumes test-ui skill users have Playwright browsers installed (`npx playwright install chromium`). The skill does not auto-install browsers.

11. **Skill Versioning**: Initial implementation does not include skill versioning (all skills are version 1.0.0). Breaking changes to skill interfaces require manual updates.

12. **No Skill Composition**: Skills operate independently. There is no mechanism to chain skills (e.g., `generate-chapter` → `translate-urdu` → `rag-ingest` pipeline). This is a future enhancement.

## Dependencies

- **Claude Code CLI**: Required to invoke skills via `@skill:name` commands. Skills are Markdown files interpreted by the CLI.
- **OpenAI API**: Required for embedding generation in rag-ingest skill and optional content generation in generate-chapter skill.
- **Qdrant Cloud**: Vector database for storing chapter embeddings. Free tier (1GB storage, 1M vectors).
- **Docusaurus v3.x**: Static site generator framework. Skills must generate compatible MDX syntax.
- **React 18**: UI framework for landing page components and language context.
- **React Context API**: State management for Urdu/English toggle (no Redux or external state library required).
- **localStorage API**: Browser storage for persisting language preference.
- **Playwright**: End-to-end testing framework for test-ui skill.
- **Tailwind CSS**: Utility-first CSS framework for landing page styling (hero section, feature grid).
- **lucide-react**: Icon library for feature cards and navbar toggle button.
- **Feature 003-better-auth**: Existing authentication system with hardware profiling. This feature integrates with (not modifies) the Sign-Up modal.

## Out of Scope

1. **Skill Marketplace or Registry**: No centralized repository for sharing skills between projects. Skills are local to this project in `.claude/skills/`.
2. **Skill Analytics**: No tracking of skill usage frequency, success rates, or performance metrics.
3. **Automated Skill Testing**: Skills themselves are not unit-tested. The test-ui skill tests UI components, not the skill framework.
4. **Full Content Translation**: Only navbar is translated to Urdu in this phase. Translating all textbook chapters to Urdu is future work.
5. **Urdu Input Validation**: Sign-Up modal and other forms do NOT accept Urdu text input (only English/ASCII). Urdu is display-only.
6. **Right-to-Left (RTL) Layout**: Urdu UI is rendered in left-to-right layout (Roman Urdu script). True RTL support for Arabic Urdu is out of scope.
7. **Content Personalization Based on Language**: Showing different content to Urdu vs. English users is not implemented (all users see the same chapters).
8. **Offline Mode for Skills**: Skills require internet for API calls (OpenAI, Qdrant). No offline caching or local LLM support.
9. **Skill Parameter Validation**: Skills accept string arguments and perform basic validation (non-empty check). Complex validation schemas are not implemented.
10. **Multi-Language Toggle (Beyond Urdu/English)**: No support for additional languages (e.g., Arabic, Hindi, Chinese). The toggle is binary: Urdu or English.
11. **Skill Permissions or Access Control**: All developers with CLI access can invoke any skill. No role-based restrictions.
12. **Skill Output Versioning**: Skills overwrite files without creating backups or version history. Use git commits to track changes.
13. **Dynamic Skill Loading**: Skills must be pre-defined in `.claude/skills/`. Users cannot define custom skills at runtime without creating Markdown files.
14. **Skill Composition or Pipelines**: No workflow orchestration. Each skill runs independently. Chaining skills requires manual sequential execution.
15. **Accessibility Compliance (WCAG AA)**: Landing page will follow basic accessibility practices (semantic HTML, alt text), but formal WCAG AA certification is out of scope.
